# 排障：跑起 CSI 之后 Wi-Fi 变慢

> 本文是实测复现结论；完整定位过程见
> <https://okwujun.pw/zh/wifi-slow-troubleshooting/>。

## 症状

- 只有 **AP → 客户端（下行）** 方向变慢：AP 侧 `tx bitrate` 被压到 `VHT-MCS0`（约 13.5Mbps）；
- 上行正常（数百 Mbps）；
- 空闲后就塌陷，且**持续流量也恢复不了**。

## 高置信度触发因素 1：固件 VoW ATF（默认开启）

```bash
cat /sys/kernel/debug/ieee80211/phy*/mt76/vow_atf    # 1 = 开启（默认）
echo 0 > /sys/kernel/debug/ieee80211/phy*/mt76/vow_atf
```

实测对照（空闲 60 秒后连续 6 次内网下载）：

| vow_atf | 结果 |
| :--- | :--- |
| 1 | 9.5 / 7.3 / 9.5 / 7.4 / 9.6 / 7.2 Mbps（36 秒持续下载也恢复不了） |
| 0 | 7.8 / 8.8 / 20 / 146 / 387 / 393 Mbps（十几秒内爬回满速） |

持久化：`/etc/init.d/mt76-wifi-tune`（开机）+ `csi-watchdog`（每分钟重放）。

## 触发条件 2：40MHz 客户端接入 80MHz BSS

老客户端（例如 Broadcom 的 Mac）只协商 40MHz，在 80MHz BSS 里会周期性塌陷：

| 配置 | 空闲 60 秒后连续 6 次下载 |
| :--- | :--- |
| HE80（80MHz） | 7.4 / 7.3 / 9.3 / 9.5 / 9.6 / 9.6 Mbps（全塌陷） |
| HE40（40MHz） | 384 / 375 / 328 / 416 / 411 / 419 Mbps（6/6 稳定） |

切换：`sh /usr/bin/wifi-htmode HE40`（日常） / `HE80`（CSI 高精度）。

以上是同一设备、同一客户端上的可重复 A/B 结果。由于没有读取固件内部速率状态，工具包不对
具体寄存器或 PPDU 字段作未经验证的归因。

## 其它必须知道的坑

1. 未设置 **frame-type 过滤**（`ctrl=1,0,0,34`）→ 一条数据都没有；
2. 未把目标 MAC 加入过滤表 → 抓不到目标设备；
3. Wi-Fi 固件不是 20260515 → 使能成功但没有上报；
4. 用公网做吞吐测试 → 结果不可复现，请用内网流量源；
5. 客户端空闲时帧率为 0 属正常（CSI 只在有包时上报）。
